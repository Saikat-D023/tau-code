# Claude uses a developer API key, not subscription OAuth

`ClaudeClient` authenticates to `api.anthropic.com/v1/messages` with a real Anthropic developer API key (`x-api-key`), sourced from a pasted key (`taucode auth`) or `ANTHROPIC_API_KEY`. It does not offer a "log in with your Claude Pro/Max subscription" OAuth flow, even though that pattern was implemented for OpenAI (see [docs/adr/0002](./0002-oauth-first-provider-auth.md)) and was originally planned symmetrically for Claude too.

We built the Claude OAuth flow first and ran it against a real Claude.ai account during development. Two things fell out of that: the initial parameters (missing a required `code=true` flag, and using an independent `state` instead of reusing the PKCE verifier) were fixable reverse-engineering mistakes — but getting the resulting token to actually work against the Messages API requires every request to send the system prompt `"You are Claude Code, Anthropic's official CLI for Claude."` verbatim. Anthropic's backend uses that string to gate subscription-authenticated access to the official Claude Code client. Sending it from taucode means claiming to *be* a different Anthropic product to get access a third-party tool isn't meant to have — not a grey-area implementation detail, but active client-identity spoofing. This exact pattern is documented in OpenCode's own issue tracker as getting real users' Claude accounts banned.

We rejected that trade-off. A Claude Pro/Max subscription doesn't include Messages API access on its own — an Anthropic API key is a separate, ToS-compliant credential billed independently, same relationship `OPENAI_API_KEY` has to a ChatGPT Plus subscription. The cost: taucode can't offer "just log in with your existing Claude subscription" for Claude the way it can for OpenAI — the pitch is asymmetric across providers, and a user without a separate Anthropic API key can't use Claude through taucode at all.

If Anthropic ever offers a supported way for third-party tools to use subscription-derived access, this is the ADR to revisit.
